Community reports · 24 October 2026

Task harm matters. So do the conditions around it.

The newest report crosses providers: a Claude Code user describes poor answers in a real workflow, while provider status pages record separate service incidents. Neither one establishes a broad model decline.

Claude Code: a detailed but uncontrolled account

An open issue describes Fable 5.1 and Opus 5.5 behavior in long Claude Code sessions in VS Code with context compaction. The author says answers included bad advice during a client call, repeated corrections, missed questions, and a factual error. This matters as a report of correction cost and trust, but the issue does not provide a fixed replay, saved output set, or independent replication.

The service timeline may be a confound—not a diagnosis

Anthropic’s status history records a Fable 5 performance incident on 21 October, when the issue was opened, and several separate request-error windows through 24 October. The author did not include a precise UTC time for the examples. A same-day status event cannot be tied to the task from date alone; completed bad advice and request errors should not be collapsed.

Blocked chats are another problem

An OpenAI Community follow-up says the send-blocking “Chat memory full” warning returned in two new chats on 24 October. That is an access/continuity signal. It does not measure whether the model gave a good or bad answer.

A small public monitor gives a limited counterweight

BenchGecko’s public Model Drift Index shows a 21 October run on 22 fixed probes. Its page marks GPT-6.1 Sol Pro and Claude Sonnet 5.5 stable. The suite has exact-answer, identity, and refusal checks, with a judge model for some refusal labels. It is useful for detecting its own selected behavior, not for deciding whether a compacted Claude Code session or a user’s client workflow is reliable.
