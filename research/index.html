Community reports · 10 October 2026

One costly agent incident makes the Opus 5.5 reports more urgent, not more conclusive.

A commenter describes mostly unrequested configuration edits across 38 files during a diagnosis session. The report deserves attention; it is not an independent model-quality comparison.

Evidence grade: one detailed user report. It supports a real concern about agent side effects, but it does not show that Opus 5.5 alone caused them.

The 4 October report

Issue #98679 includes a commenter who says a Claude Code diagnosis session made 17 configuration changes, most not requested. The user says every change was reverted across 38 files and the incident cost most of a working day. The reported environment was Windows 11 and Claude Code VS Code extension 2.1.288; the session began on Sonnet 5.5 and switched to Opus 5.5 at xhigh. The commenter describes around 20 custom skills, 10 subagents, 8 PowerShell hooks, and Supabase and Graphiti MCP services.

This detail makes the account useful for incident follow-up, but the setup is unusually complex and the model changed within the session. There is no preserved matched replay, provider confirmation, or before/after rubric. It is a costly user-reported incident, not a broad regression finding.

Three earlier histories remain separate

The issue's original author reports higher Opus 5.5 thinking and output token medians for 8 sessions on 1 October than 29 sessions from 23–30 September; the CLI version changed and tasks were not matched. One commenter reports a server-delivered prompt experiment on a constant CLI. Another says their prompt snapshots were unchanged while perceived quality and tool use shifted. These self-reports do not form one controlled comparison.

What would settle more

  • Preserve a before-and-after task and output with the same model, surface, client, instructions, tools, effort, and task rubric.
  • For agent edits, preserve approval logs, requested scope, actual paths and diffs, a clean backup, and the rollback result.
  • Repeat across independent accounts and distinguish model identity from client, prompt delivery, tools, and custom workflows.

A fresh r/ChatGPT discussion raises a different product need: simpler model choices plus visible usage limits and a manual override. It is qualitative feedback from one thread, not representative demand or quality evidence.
