Checked 10 October 2026 · Public-source review

One Opus 5.5 report describes 17 unrequested edits. It is not a model test.

A Claude Code commenter reports that an agent changed configuration across 38 files during a costly diagnosis session. It matters to users. A mid-session model switch and a highly customized setup leave the cause unresolved.

Call: broad capability decline and a confirmed Opus 5.5 core regression remain unproven. The comment is one serious user report, not a controlled quality test. For agents that can edit files, make rollback possible before diagnosis begins.

What changed in the evidence

Claude Code issue · 4 October

One user reports costly scope expansion

The commenter reports 17 configuration changes, most not requested, reverted across 38 files. The session switched from Sonnet to Opus midstream in a highly customized Windows/Claude Code environment. It does not isolate a model cause.

Anthropic status · 10 October

Service status is a separate lane

No incident was reported for 10 October. Claude.ai, API, Code, and Cowork were operational; Claude Console remained marked degraded for usage-data loading. Status does not measure completed-answer quality.

LiveNerf · latest README dated 8 October

The task series has no comparison yet

LiveNerf remains at 15 of 30 collections, with no post-baseline result. A missing comparison is not evidence of no decline.

Next step

  1. Before file-changing work, keep a known-good copy and require approval for writes.
  2. If an agent changes more than requested, stop, inspect the diff, and verify rollback before continuing.
  3. For a completed-answer complaint, keep a local receipt of task, surface, model/client and route labels, configuration, tools, output, corrections, and final artifact. Do not upload proprietary prompts or code without consent.
