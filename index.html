Current call · 12 September 2026 · 12:00 UTC
NO BROAD CORE-CAPABILITY DECLINE PROVEN

A tool call can fail without the model getting dumber.

The newest evidence is more concrete than a mood swing: a Google forum report quotes GCP Support attributing a Gemini Deep Research MCP failure to a backend change that skipped tool invocation. A separate Gemini video workflow died after 23 processing calls. Codex logs point to faster runtime consumption and shorter usable windows. These are real system failures—not proof of a broad cross-model weight decline.

Confidence: high for the current Claude component snapshot · medium-high for the detailed Gemini MCP report with quoted support attribution · medium for the Agentic Video and Codex runtime leads · low for prevalence, account attribution, or broad capability regression.

What changed? In the Gemini MCP report, the system completed initialize and tools/list, then sent no tools/call. Max still produced a substantive report without the private data. A quoted support reply says the issue came from the backend. No public fix timeline is available, so this is a narrow, high-consequence product signal—not a model-weight verdict.

The answer in one screen

Grounding lane

Discovery is not execution

Gemini Deep Research can reportedly see the remote MCP tool and still not run it. The final prose can look complete while its private-source grounding is absent.

Tool-loop lane

Another Gemini path hits a boundary

An Agentic Video report says seven of seven full-length files reached 23 processing calls and 22 results before an internal error. Later attempts returned too-many-tool-calls; usage was not exposed.

Usable-window lane

Codex got faster in the wrong way?

A five-versus-five public telemetry comparison reports more model steps per minute and higher observed allowance burn in runtime 0.150. It measures time and quota, not answer quality.

Surface lane

Claude remains partly down

Official status lists Cowork on Windows in partial outage while claude.ai, Console, Claude API, and Claude Code are operational. A work surface can fail while the model is available.

When your agent feels worse

  1. Save provider, surface, visible and effective model, runtime, plan, effort, route, transport, context, task, and wall-clock time.
  2. Record the tool lifecycle: initialize, list, call, result, and final. A missing call is not the same failure as a failed call.
  3. Verify the final artifact and grounding. Then record retries, output tokens, allowance movement, and cost separately from answer quality.
  4. Replay the same task on a stable surface before switching or naming capability decline.

Counterweights

Bug Hunt Bench remains a cross-sectional planted-bug comparison whose displayed Astra and Fable 5.1 maxima exceed Sol. Beyond Benchmarks still shows high rolling Astra outcomes with changed cost and friction values. Marginlab Codex is nominal; its Claude Code tracker is still collecting a baseline. These are useful counterweights with different estimands, not a broad time series.
