Checked 15 October 2026 · Public-source review

Two post-resolution Codex failures are reported. Broad model decline remains unproven.

Current call: request and access problems are still reported on specific Codex paths; public evidence does not establish broad GPT-6.1 Sol capability decline. OpenAI marked its 13 October GPT-6.1 Sol Codex/Work performance issue resolved at 16:36 UTC. One Windows Pro account later reported capacity errors across seven models; a separate user diagnostic reported a server error tied to one saved reasoning item. The two reports describe different failures and do not establish a shared cause.

If Codex fails: check the current status page, keep the original conversation unchanged, and record the model, surface, client, effort, context, time and exact error. If useful and safe, test a small non-sensitive task in a fresh conversation on the same settings. A no-output error is not a wrong answer.

Separate the failure modes

The Windows report is an account-level capacity signal across several models. The saved-history report is a request error tied to one particular input on GPT-6.1 Sol. Both stop the request before a completed answer can be judged. Neither report shows that the model returned a worse answer on a matched task.

The first saved-history report predates the status incident; the later replay was tested after the status page marked its event resolved. The timeline makes the distinction worth monitoring, but no provider log correlation explains whether the reports are related.

Do not change valuable conversation history based on one public workaround. Preserve it, keep private prompts and logs private, and share request details only through a provider's official support channel.

What to do next

  1. Check the current status page for the product surface and model you use.
  2. For a capacity or server error, note the time, plan/allowance display, client, model and surface; do not label the event a quality failure.
  3. For a saved-history failure, keep the original unchanged. If safe, try a small non-sensitive task in a fresh conversation using the same model and settings.
  4. For an answer that completes but seems worse, repeat the same task under the same surface, model, effort and tools; record correctness and correction burden separately from speed and allowance.
